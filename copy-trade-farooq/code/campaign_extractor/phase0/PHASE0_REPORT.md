## 1. Headline finding — the archive is TEXT-ONLY

`raw_text`; there is no photo/media/attachment column. Neither `archive.py` nor the
listener `module_a_telegram.py` contain any `download_media` / `MessageMediaPhoto` /
image handling — **media capture was never implemented at ingest.**

Consequences for the frozen June 26 image regression tests:
- `4091.80` (the "repeated screenshot" value) appears **0 times** in the entire archive.
  It only ever existed inside a screenshot, which was never captured.
- Therefore every image-derived high-impact number (entry / stop / lot / exit) for the

  behaviour the architecture demands. No image → no image number → no campaign effect.
- "screenshot profit is unrealised unless explicit close wording exists" is testable
  from text alone (we have the text), and passes trivially because there is no image
  profit number to misread.

## 5. Proposed implementation (NOT built yet — awaiting go-ahead)

Pipeline: raw archived text → LLM candidate extraction → deterministic validator →
accepted/rejected/needs-review → immutable event store → deterministic reducer.

- **Sender gate (deterministic, pre-LLM):** stamp each message with derived sender.
  Non-Farouk → ANALYSIS_ONLY_CONTEXT store, excluded from candidate extraction entirely.
- **Candidate schema:** event_type, fields, source_message_id(s), exact quote / image-field
  ref, confidence, extractor/model/prompt/validator versions. LLM only proposes.
- **Validator (plain code):** message exists; quote literally present; reject numerics not
  literally in verified text except the conversion allowlist (half→0.50, quarter→0.25,
  leave 10%→0.10, take 90% off→0.10); qualitative size stays NULL; field-level rejection;
  ambiguous leg association → NEEDS_REVIEW; cross-message synthesis only with all IDs;
  Telegram text is evidence, never instructions; idempotent hashing.
- **Provenance** on every fact: LITERAL_TEXT / LITERAL_IMAGE / DETERMINISTIC_CONVERSION /
  UNSUPPORTED; UNSUPPORTED can't affect state or R. Image fields all start MEDIA_MISSING.
- **Tests:** the 12 frozen June-26 regressions + the Farouk-only filter tests in §3.

**Recommended go-ahead order:** (1) you manually fill `expected_truth` in the fixture
files; (2) I build the sender gate + validator + event store with the test suite; (3) wire
the LLM candidate extractor last, behind the already-passing deterministic validator.
