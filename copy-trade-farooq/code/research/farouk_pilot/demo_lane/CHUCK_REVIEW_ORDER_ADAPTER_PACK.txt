4. THE TWO 6a TESTS CALLED OUT EXPLICITLY  (the heart of the design)
--------------------------------------------------------------------------------
6a-1  STOP-ATTACHMENT FAILURE
   Scenario: broker accepts the entry but REJECTS or OMITS the protective stop.
   Proven: executor CLOSES any filled quantity (close-only) + CANCELS the entry +
           raises alarm UNPROTECTED_POSITION_PREVENTED + HALTS.
   Sub-cases:
     [6a-1]  entry FILLED, stop rejected -> filled qty closed (positions == 0),
             entry cancelled (orders == 0), alarm raised, trace shows
             PROTECTIVE_CLOSE_FILLED + PROTECTIVE_CANCEL_ENTRY.
     [6a-1b] entry PENDING, stop rejected -> pending entry cancelled (never fills
             unprotected), no position ever opened, alarm raised.
   Invariant proven: NO unprotected position ever remains.

6a-2  PARTIAL FILL WITHOUT VERIFIED STOP
   Scenario: order partially fills; the protective stop is not confirmed.
   Proven: CANCEL remainder + CLOSE filled portion + alarm + HALT
           (positions == 0, orders == 0, alarm raised).

Mechanism location: executor.Executor._verify_protection_or_unwind (single-source
orchestration), invoked per leg AFTER the account-id check and BEFORE the generic
seven-field reconcile, because stop-omission is a specific, known-dangerous case
that needs an ACTIVE unwind, not just a halt.
